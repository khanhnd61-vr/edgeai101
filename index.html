Part 1 · Background

What we optimize

Six numbers describe a deployed model. Every technique in this course trades some of them against the others.

Latency

Time for one inference, in ms. For an LLM: time to first token (TTFT), then time per generated token.

Throughput

Work per second: tokens/s for an LLM, frames/s for vision, actions/s (Hz) for a robot policy.

Peak memory

The most RAM needed while running: weights, activations and caches. Exceed it and the OS kills the app.

Energy

Joules per inference. It sets battery life and heat, and heat triggers thermal throttling that lowers speed.

Size on disk

Bytes to download and store. It matters for app stores, over-the-air updates and microcontroller flash.

Quality

Task performance after optimization: answer quality for an LLM, task success rate for a robot.

Parameter count and FLOPs are only proxies. The numbers that count are measured on the target device.

Part 1 · Background

Where the time goes when an LLM generates

Generation has two phases with different bottlenecks. Knowing which one limits you tells you which optimization will help.

Phase 1 · Prefill

Read the whole prompt at once

All prompt tokens pass through the network in one batch. That is a lot of arithmetic at once, so the limit is compute. Prefill sets the time to first token.

Phase 2 · Decode

Write the answer one token at a time

Each new token is one full pass, and each pass reads every weight once. The limit is how fast memory can deliver the weights: memory bandwidth.

tokens/s ≲ memory bandwidth ÷ model size
50 GB/s ÷ 4 GB ≈ 12 tokens/s at best

A rule of thumb for decode, not a law. It explains why a 4-bit model is faster than a 16-bit one, not just smaller: there are fewer bytes to move per token.

A weight is a bit pattern. Fewer bits means fewer distinct values the weight can take.

One weight, step by step

The error is 0.04. Note that −0.31 also became −3: two different weights are now identical.

Part 2 · Quantization

Choosing the scale and zero-point

The grid should cover the range the values actually occupy. Two layouts are common, one for each typical shape of data.

Symmetric · used for weights

s = max|r| / (2^(b−1) − 1), z = 0

Weights are roughly centred on zero, so the grid is centred too. With z = 0 a multiply needs no offset correction.

Asymmetric · used for activations

s = (r_max − r_min) / (q_max − q_min)
z = round(q_min − r_min / s)

After ReLU or GELU the values are one-sided. A centred grid would waste half its levels, so the grid is shifted with z.

Orange mark: real zero. It must sit exactly on a grid point, so that zeros (padding, ReLU outputs) stay exact.

Part 2 · Quantization

Two kinds of error: rounding and clipping

Most values sit in a narrow bulk; a few outliers sit far away. The range you pick decides which error you pay.

Range = min to max

Large rounding error

Nothing is clipped, but the step s is wide. Almost every level is spent on empty space, and the bulk is described by only a few of them.

Range = clipped

Small rounding error, some clipping error

The step is fine where the data is. Outliers saturate at the last level and lose their true value. Usually the better trade.

rounding error ≤ s / 2 per value

Calibration is the choice of range from sample data: min–max, a percentile such as 99.99%, or the range that minimizes mean squared error.

Part 2 · Quantization

Granularity: how many scales

One scale for a whole weight matrix is rarely enough. Each coloured region below shares one scale s.

Per tensor

One s for the whole matrix. Simplest and cheapest, but one large row forces a coarse grid on all the others.

Per channel

One s per output row (one neuron or one convolution filter). The standard for INT8 CNNs: almost free and much more accurate.

Per group

One s for every small block of consecutive weights, for example 32. The standard for 4-bit LLM formats.

Finer granularity means less error and more metadata. A 4-bit code plus one 16-bit scale per 32 weights costs 4.5 bits per weight.

Part 2 · Quantization

QAT and the straight-through estimator

Rounding is a staircase: its gradient is zero almost everywhere, so backpropagation stops.

forward: round(x), a staircase

backward: treated as slope 1

x

forward: ŵ = s · round(w / s)
backward: ∂L/∂w ≈ ∂L/∂ŵ

Forward pass. The real quantizer runs, so the loss is computed with the weights the device will actually use.

Backward pass. The gradient is copied straight through the rounding step as if it were the identity. It is set to zero only outside the clipping range.

What is trained. A full-precision “latent” copy of each weight keeps receiving small updates. Over many steps it drifts until its rounded value is the one that lowers the loss.

This node is called fake quantization. The estimator is usually credited to Bengio et al., 2013.

Why LLMs need their own methods

The classic INT8 recipe was built for CNNs. Three things break it for large transformers.

Activation magnitude per channel in one layer (illustrative)

A handful of channels are 10–100× larger than the rest. One scale for the whole tensor either clips them or crushes everything else to zero.

1 · Too big to retrain

Retraining billions of weights is out of reach. Methods must work post-training, layer by layer, from about a hundred calibration sequences.

2 · Activation outliers

The spikes on the left make activations hard to quantize, so weight-only quantization is the default for LLMs.

3 · Weights are not equally important

A weight that multiplies a large activation matters far more than one that multiplies a tiny one.

but min ‖W·X − Ŵ·X‖² on calibration inputs X

Part 2 · Quantization

GPTQ: round one column, repair the rest

Round one column of a layer, then adjust the columns not yet rounded so the layer’s output is unchanged.

already rounded, now frozen

the column being rounded

still full precision: nudged to cancel the error

goal, per layer: min ‖W·X − Ŵ·X‖²
H = 2·X·Xᵀ (from calibration inputs X)

1 · Measure

Run about a hundred sequences through the model and record each layer’s inputs X. H captures which inputs are large and how they are correlated.

2 · Round a column

Snap every weight in the column to the grid. This leaves a known error.

3 · Compensate

Spread the opposite of that error over the remaining columns, weighted by H⁻¹. If two inputs usually move together, a weight on one can make up for the other.

Frantar et al., 2023. No gradients, no retraining, even at 175B parameters.

AWQ: protect the weights that matter

About 1% of weights feed on the largest activations and carry most of the quality. AWQ makes those weights bigger before rounding, so the same rounding step hurts them less.

Why scaling helps

The grid step stays about the same, but the important weight is now s times larger. Its error, relative to its size, shrinks by about s.

How s is chosen

s_j = (mean |x_j|)^α

Channels with large activations get large s. A grid search over α between 0 and 1 picks the value with the smallest output error.

Why it is popular

No backpropagation and little calibration data. Every weight keeps the same bit width, so the file stays simple for hardware. Lin et al., 2024.

The 4-bit sweet spot

For the same memory, a larger model at 4 bits usually beats a smaller model at 8 bits. Below about 3 bits the opposite holds: pick a smaller model.

Mixed precision

Layers differ in sensitivity. Embeddings and the first and last layers often get more bits; the bulk in the middle gets fewer.

Weights take only three values, −1, 0 and +1. That is log₂ 3 ≈ 1.58 bits. A matrix product becomes additions and subtractions.

It works only because the model is trained that way from scratch.

Part 3 · Distillation

The distillation loss

The student answers to two supervisors at once: the true labels and the teacher.

L = α · CE(y, p_s) + (1 − α) · T² · KL(p_t ‖ p_s)

Hard-label term

Match the ground truth

Ordinary cross-entropy between the true label y and the student’s prediction at T = 1. It keeps the student anchored when the teacher is wrong.

Soft-label term

Match the teacher

KL divergence between the teacher’s distribution p_t and the student’s p_s, both computed at temperature T. It is zero only when the two distributions are identical.

The factor T²

Keep the two terms balanced

Dividing logits by T shrinks the soft term’s gradients by about 1/T². Multiplying by T² restores them, so α means the same thing at any temperature.

α weights the two supervisors. In practice the teacher term usually gets most of the weight. Hinton, Vinyals and Dean, 2015.

Part 3 · Distillation

Where distillation fits

It is the most powerful compressor in this course, and the most expensive one.

Use it when

You need a much smaller model, 5× or more, or a different architecture altogether. Quantization and pruning cannot change a 12-layer network into a 4-layer one.

What it costs

A full training run for the student, plus a teacher forward pass for every training example. You need data, a training pipeline and GPU time.

How it combines

Distill first, then quantize the student. A teacher also helps recover quality after the other techniques: the full-precision model can supervise its own quantized or pruned copy.

Where it breaks

A student that is too small cannot follow a much larger teacher; an intermediate-size “assistant” teacher can bridge the gap. The student also inherits the teacher’s mistakes.

Distillation changes what the model is. Quantization and pruning change how an existing model is stored. They stack.

Pruning and sparsity

Remove the parts that contribute least: single weights, whole neurons, attention heads, layers, or even input tokens.

The idea: most connections barely matter

A trained network has more weights than it needs. Pruning sets the least useful ones to zero.

35 connections before, 14 after: a sparsity of 60%.

sparsity = zero weights ÷ all weights

Why it is possible

Extra capacity helps training, but the finished network does not use all of it. Most weights sit near zero and barely change the output.

Why it is not free

Each removed weight shifts the output a little. The rest are fine-tuned, or adjusted in closed form, to compensate.

The classic result

Deep Compression removed 9 in 10 connections of AlexNet, then quantized and entropy-coded the rest: 35× smaller, same accuracy. Han et al., 2016.

Part 4 · Pruning

What to remove: three patterns

The same number of zeros can be arranged in very different ways. The arrangement decides whether hardware can profit. Blue cells are kept, pale cells are zero.

Unstructured

Any individual weight can go. Keeps the most accuracy at a given sparsity, but the matrix keeps its shape, so speed needs special sparse kernels.

Semi-structured, N:M

A fixed quota in every small group: here 2 zeros in each 4. Regular enough for hardware: recent NVIDIA GPUs have dedicated support for 2:4.

Structured

Whole rows and columns go: neurons, channels, heads, layers. The matrix becomes a smaller dense one, faster on any hardware, but accuracy suffers sooner.

Part 4 · Pruning

Deciding which weights to remove

Every method gives each weight a score and removes the lowest. The methods differ in how much they know about the data.

Magnitude

|w|

Small weights go first. Needs no data at all. The baseline that is hard to beat when fine-tuning follows.

First-order

|w · ∂L/∂w|

A Taylor estimate of how much the loss changes if w becomes zero. Needs gradients on some data.

Second-order

w² / (2·[H⁻¹]_ii)

Uses curvature, and also tells how to adjust the surviving weights. Optimal Brain Surgeon, 1993; the basis of SparseGPT.

Activation-aware

|w| · ‖x‖₂

Weight size times the size of the input it multiplies. One forward pass, no gradients. Wanda, 2024.

Why magnitude alone can mislead

w = 0.1, input ≈ 50 → output 5.0

w = 1.0, input ≈ 0.2 → output 0.2

Magnitude pruning would delete the first weight and keep the second. The activation-aware score gets it right, the same insight as AWQ in Part 2.

One-shot

Cut to the target in a single step, then fine-tune, or not at all. Fast. Fine at moderate sparsity, and the only option for LLMs too large to retrain.

Gradual

The lottery ticket hypothesis

A dense network contains a sparse sub-network that, trained alone from the same starting weights, matches the full one. Finding it still means training the dense network first. Frankle and Carbin, 2019.

Where U and V come from

The singular value decomposition gives the best rank-r approximation of W: keep the r largest singular values and drop the rest.

The catch

LLM weight matrices are not very low-rank, so plain SVD loses a lot. Practical methods weight the decomposition by the activations and fine-tune afterwards.

LoRA keeps W frozen and trains a low-rank update ΔW = B·A. It is the standard cheap way to recover quality after pruning or quantization.

Neural architecture search: the loop

NAS automates the trial-and-error loop that a human designer runs. Every NAS method is a choice for each of three parts.

1 · Search space

What can be built

The allowed layer types, depths, widths, kernel sizes and connections.

2 · Search strategy

What to try next

Reinforcement learning, evolution, or gradient descent picks the next candidate.

3 · Evaluation

How good it is

Train the candidate and measure it, or estimate its quality with a cheaper proxy.

feedback: each score guides the next choice

The cost is in step 3. Training one candidate takes hours, and a search tries thousands. Most progress in NAS has come from making evaluation cheaper.

The space matters most. A search can only find what the space contains. A good space, designed by people, is half the result.

From model file to machine code

A trained model is a description of a computation. Four more steps turn it into instructions a particular chip executes.

1 · Train

Framework model

PyTorch code and weights. Flexible, built for research.

2 · Export

Portable graph

A fixed list of operators and tensors: ONNX, GGUF, .tflite, .pte.

3 · Optimize

Graph rewrite

Fuse operators, fold constants, plan memory. Outputs stay the same.

4 · Lower

Kernels chosen

Each operator is mapped to an implementation for this chip.

5 · Run

Runtime

Loads weights, manages memory and threads, calls the kernels.

Style A: interpreter plus kernel library

The runtime walks the graph and calls a pre-written, hand-tuned kernel for each operator. Portable and easy to debug. LiteRT, ONNX Runtime, ExecuTorch and llama.cpp work this way.

Style B: ahead-of-time compiler

A compiler generates code specialized for this exact model on this exact chip, and can tune it by measuring. More speed, less portability. TVM, IREE and a TensorRT engine build work this way.

Before any kernel runs, the graph is rewritten into an equivalent one with fewer, larger operators.

At inference BatchNorm is just a fixed scale and shift, so it can be absorbed into the convolution’s weights once, offline. One pass over memory instead of three.

Operator fusion

Merge neighbours into one kernel so intermediate tensors are never written to memory.

Constant folding

Anything that depends only on the weights is computed once at build time, not on every run.

Dead-code elimination

Remove training-only parts such as dropout, and branches whose result is unused.

Memory planning

Tensors whose lifetimes do not overlap share one buffer. This decides whether a model fits on a microcontroller at all.

Part 6 · Kernels and runtimes

What a kernel is

A kernel is the inner loop that implements one operator for one kind of processor.

Matrix multiplication, where an LLM spends almost all its time

for i in rows(A):
  for j in cols(B):
    for k in cols(A):
      C[i][j] += A[i][k] * B[k][j]

Correct, and very slow. It pretends that every memory access costs the same and that the processor does one multiply at a time. Neither is true.

Libraries such as XNNPACK, KleidiAI, oneDNN, cuDNN and CMSIS-NN are collections of these kernels, written per processor family.

Four ideas make it tens of times faster. The next slides take them in turn

1 · Respect the cache

Work on tiles small enough to stay in fast memory, and lay the data out so it is read in order.

2 · Use SIMD

One instruction processes 4, 8 or 16 numbers at once.

3 · Use every core, carefully

Split the work across threads, or hand it to a GPU or NPU.

4 · Pick a better algorithm

Reorganize the arithmetic so there is less of it.

Blocking: finish one cache-sized tile, then move on

Why the naive loop is slow

It walks down a column of B, touching a different part of memory at every step. On a large matrix most accesses go to main memory.

Blocking

Cut the matrices into tiles that fit in cache and finish one tile before the next. Each value fetched is reused many times.

Packing

Copy the tile into a small buffer in exactly the order the inner loop reads it. Sequential reads suit the hardware prefetcher.

What cannot be blocked away

A multi-gigabyte LLM never fits in cache. Each token streams every weight from main memory: the bandwidth limit from Part 1.

Idea 4: pick a better algorithm

One operator can be computed in several equivalent ways. Four that matter in practice.

Convolution

im2col + GEMM

Unroll every k × k window of the input into a row. The convolution becomes one large matrix multiply and reuses the best-tuned kernel. The price is a big temporary copy; XNNPACK’s indirect convolution swaps it for a table of pointers.

3 × 3 convolution

36 → 16

Winograd

Computing a 2 × 2 patch of outputs takes 16 multiplications instead of 36, a 2.25× saving paid for with extra additions. It is less robust at low precision, so it suits float kernels best.

Attention

FlashAttention

Attention normally writes an N × N matrix to memory. FlashAttention computes the same result in tiles that fit fast on-chip memory and never stores it. Memory grows linearly with sequence length; the output is exact.

Integer inference

Fixed-point rescaling

After an int8 multiply, the result must be rescaled by a real number M. Kernels do it with an integer multiply and a bit shift, M ≈ M₀ · 2⁻ⁿ, so the whole network runs without floating point.

Compilers and auto-tuning

Hand-writing a kernel for every operator on every chip does not scale. A compiler can search for the fast version instead.

Algorithm

candidate schedules

Fastest schedule

algorithm: C = A × B
schedule: tile 64×64, vectorize, 4 threads

The algorithm states the mathematics; the schedule states loop order, tiling, vectorization and threading. Changing the schedule changes only the speed. The split comes from Halide.

Searching the schedules

Thousands of schedules are valid for one operator. An auto-tuner tries them on the device, or asks a learned cost model, and keeps the fastest.

Apache TVM

The best-known open compiler of this kind. Its current tuner is MetaSchedule; AutoTVM and Ansor were earlier generations. MLC-LLM is built on it.

TensorRT

Builds an “engine” for one NVIDIA GPU: fuses layers, chooses precision, times alternative kernels and keeps the fastest. By default it runs only on the GPU model and version that built it.

Part 6 · Kernels and runtimes

The KV cache

The most important runtime optimization for LLMs: never recompute what earlier tokens already produced.

Without a cache

Producing token 6 redoes the work of tokens 1 to 5.

With a cache

Blue rows are stored. Only the new row is computed.

KV bytes = 2 × layers × tokens × kv_heads × head_dim × bytes

Worked example: a 7B model with 32 layers and 32 heads of 128 dimensions, in FP16, stores 0.5 MB per token. A 4,096-token context costs 2 GB, on top of the weights.

What is stored

For every layer, the key and value vectors of every token so far. They never change once computed, because attention only looks backward.

The trade

Work per new token drops from quadratic to linear in the context length. The price is memory that grows with every token.

Keeping it small

Grouped-query attention stores fewer KV heads. The cache itself can be quantized. And context length is a budget: set it on purpose.

Making a VLA fast enough

Every lever below is a technique from an earlier part, applied to the control loop.

Action chunking

Predict the next H actions in one inference and execute them while the next inference runs. One 73 ms pass of π0 yields 50 actions.

Fewer denoising steps

Each step is one pass of the action head. Step distillation from Part 3 cuts 10 steps towards 1–4.

Run the VLM once

The backbone processes the observation a single time. Its KV cache is reused by every denoising step: in π0, 32 ms once, then 27 ms for all ten steps.

Fewer tokens, fewer layers

SmolVLA feeds 64 visual tokens per frame and uses only the first half of its VLM’s layers. Token and layer pruning from Part 4.

Parallel decoding

Emit all action dimensions of a chunk in one pass instead of token by token. OpenVLA-OFT reports 26× faster action generation.

Asynchronous execution

Decouple acting from thinking: the robot keeps executing the current chunk while the next one is computed.

Part 7 · LLM, VLM, VLA

How to measure

An optimization only counts once it is measured, on the device, in conditions that resemble real use.

On the target

A laptop number says little about a phone. Build for the real device and time it there, with the real runtime and the real thread settings.

Warm, then sustained

Discard the first runs: they include loading and compilation. Then run long enough for the chip to heat up and report the steady state.

Distributions

Report the median and a high percentile, not the best run. A robot is limited by its slowest inference, not its average one.

The right clock

For an LLM, separate time to first token from tokens per second. For a VLA, measure the full loop from camera frame to motor command.

Memory and energy

Record peak memory, not average. Where battery matters, measure joules per inference with a power meter or the system’s counters.

Task quality

Perplexity can stay flat while answers get worse. Evaluate on the task itself: answer accuracy for an LLM, success rate for a robot.

Change one thing at a time, and keep the unoptimized model as the reference for every comparison.

Part 7 · LLM, VLM, VLA

Common pitfalls

Six assumptions that sound reasonable and are regularly wrong.

The assumptionWhat actually happens
Fewer parameters means fasterParameters and FLOPs are proxies; memory traffic and kernels decide
50% sparse means twice as fastOnly with structured sparsity or dedicated sparse kernels
8-bit is safer than 4-bitDepends on the kernels: OpenVLA at 8-bit was slower and failed more
The NPU speeds everything upOne unsupported operator brings CPU fallbacks and copies
One benchmark run is enoughThe first run is slow, and a hot device is slower than a cool one
Average quality held, so all is wellSmall average changes can hide large failures on rare inputs

Every one of these is caught by the same habit: measure the real task on the real device.

Make it fit.

Make it fast.

Prove it still works.

Fast: fewer tokens and steps, a KV cache, and kernels built for the chip.
